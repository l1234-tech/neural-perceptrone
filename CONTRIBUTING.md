# Работа с проектом

Этот документ описывает безопасный рабочий процесс для C++-библиотеки нейронной сети.

## Быстрый старт

Требуются C++17-совместимый компилятор, CMake 3.15+ и Git. При первой конфигурации CMake загружает pybind11 через FetchContent, поэтому нужен доступ к сети.

```bash
git clone https://github.com/l1234-tech/neural-perceptrone.git
cd neural-perceptrone
cmake -S . -B build
cmake --build build --config Release
```

Запуск тестов зависит от платформы и генератора. Обычно это `./build/test_runner` на Linux/macOS или `build/Release/test_runner.exe` для Visual Studio на Windows.

## Основные каталоги

| Путь | Назначение |
|---|---|
| `include/` | Публичные заголовки классов и интерфейсов |
| `src/` | Реализация компонентов C++ и Python bindings |
| `tests/` | Модульные тесты |
| `data/` | CSV-датасеты |
| `scripts/` | Python-скрипты для экспериментов и визуализаций |
| `images/` | Исходные графики, используемые в документации |
| `scripts/results/` | Сохранённые примеры результатов |
| `.sourcecraft/ci.yaml` | Описание CI-сценария SourceCraft |

## Рекомендуемый процесс изменения кода

1. Создай отдельную ветку для новой функциональности или рефакторинга.
2. Меняй относящиеся к задаче файлы в `include/` и `src/`; по возможности добавляй или обновляй тесты в `tests/`.
3. Собери проект командой `cmake --build build --config Release`.
4. Запусти `test_runner` и проверь поведение затронутых сценариев.
5. Перед коммитом проверь `git status` и не добавляй локальные артефакты сборки.

## Что не следует случайно коммитить

- `build/`, временные файлы IDE и компилятора;
- виртуальное окружение Python и кэш;
- `nnlib.pyd`, `.so` и другие платформенно-зависимые бинарные файлы, если специально не требуется их распространять.

В репозитории уже присутствует бинарный `nnlib.pyd`. Этот файл намеренно не удаляется автоматически: прежде чем убирать его из истории проекта, нужно подтвердить, что он больше не нужен существующим сценариям.
